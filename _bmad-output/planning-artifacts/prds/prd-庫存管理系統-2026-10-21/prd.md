# PRD: 庫存管理系統

*Working title — 可依課程或公司需求調整正式名稱（例：多倉進銷存管理系統）。*

> **版本**：v3（2026-10-21）。v1 初稿經三路審查（評分表／領域專家／來源比對）後定案主線矛盾並補齊運算規則，**FR-1 ~ FR-29 編號維持不變**，新增需求一律從 FR-30 起編，以保既有引用有效。v3 為領域規則完整版：可用量機制、FIFO 規格、數量守恆閉合、恆等式、水位基準、折扣分攤、採購入庫數量規則、寄貨閉環、毛利口徑全部定案。

## 1. Vision

這是一套給中小型貿易／製造通路公司用的多倉庫進銷存系統。它把目前散落在 Excel、紙本單據與通訊群組裡的「商品在哪裡、還有多少、賣了多少、賺多少、該不該補貨」這五個問題，收進同一個資料庫與同一套畫面，讓倉管、採購、銷售、會計四種職能在同一份事實上工作。

對使用者而言，它把「盤點」從一個耗時、容易對不上的儀式性工作，變成每次進貨與出貨都自然留痕的日常；對管理者而言，它讓「哪個商品快斷貨了」「這單毛利是不是被折扣殺掉了」「哪個倉庫有貨可以調過去」這類問題從翻表半小時，變成一鍵查詢的報表。

本系統的成功不取決於功能數量，而取決於**一條主線的正確性**：商品 → 單據（採購單／入庫單／銷貨單／調貨單／寄貨單／調整單）→ 庫存餘額 → 成本 → 毛利。這條主線上的每一個數字都必須對得上、追得回來源、查得出是誰動的。**單據是唯一事實來源**：在手量由實體異動帳推導、可用量由在手量扣除配置量推導、成本由批次取用、收入與毛利由銷貨單認列，任何數字都能回溯到一組單據。

## 2. Target User

### 2.1 Jobs To Be Done

**倉管人員**
- 當我站在貨架前，我要輸入品名就能知道這批貨放在哪個位置、還剩多少，才能確認需要補貨或發貨。
- 當貨物進來時，我要一次把批次、供應商、數量、實際單價、位置填完，之後才知道這批貨成本多少、賺多少。
- 當我被要求出貨，我要能對著既有的銷貨單或寄貨單作業，而不是另外開一張單。
- 當我領用報廢品、盤點發現短少，我要能留下一張有原因、有核准的單據，而不是私下改掉數字。
- 當發生退貨、遺失或誤植時，我要能查得到「誰、什麼時候、動了哪個位置多少數量」。

**採購人員**
- 當我要補貨時，我要一眼看到所有低於安全水位的商品，而不是每天人工巡檢；已經在路上的貨不該再叫我重複下單。
- 當我下採購單時，商品、供應商、單價、預估金額要能帶入，我不想重複打字。

**銷售人員**
- 當客戶問「有貨嗎、在哪個倉庫」，我要立刻查出可售數量與位置，並在需要時直接開調貨單。
- 當我要報價，我要同時看到成本、折扣後售價與毛利，才不會用錯折扣賠錢。
- 當客戶要退貨，我要能開一張退貨單，不用打電話回頭改帳。

**會計人員**
- 當月底結帳，我要拿到入庫、銷貨、毛利報表，而且能從金額追溯回原始單據。
- 當我看毛利報表，我要知道口徑是未稅、且不含運費關稅，不要被數字騙了。

**管理者**
- 當我想知道公司庫存結構，我要各倉各位置的存量報表，以及各商品的銷售與毛利排行。
- 當有人離職或權限過寬，我要能停用帳號並回頭查他動過什麼。

### 2.2 Non-Users (v1)

- **POS 收銀現場人員** — 店面即時收銀、會員、付款整合不列入 v1。
- **工廠製造／BOM 排產人員** — 生產工單、配方、耗料不列入 v1。
- **外部電商平台（Shopee／蝦皮）與一般消費者** — 開放 API、電商同步、消費者下單不列入 v1。
- **客戶自助查詢者** — 客戶不直接登入系統查看庫存。

### 2.3 Key User Journeys

- **UJ-1. 倉管阿哲在收貨的時候就完成入庫。**
  - **Persona + context：** 倉管阿哲，公司唯一的倉管人員，負責南港倉的收貨與上架。
  - **Entry state：** 已登入（倉管角色），在收貨區，手上有供應商送來的貨與對應採購單編號。
  - **Path:** ① 開啟「入庫」並選擇對應的採購單 → ② 系統帶出商品、待入庫數量、預估單價，阿哲輸入實際到貨數量與**實際單價**、並指定放置的**庫存位置** → ③ 系統即時顯示該位置的庫存變化預覽 → ④ 確認過帳。
  - **Climax：** 畫面顯示「入庫完成：批次 B-20260415-001 已入南港倉 A-03，數量 120，實際單價 NT$45」，阿哲知道這批貨從此有位置、有成本、有紀錄。
  - **Resolution:** 他回到待處理清單，剩下兩筆待入庫。
  - **Edge case:** 實際到貨數量少於採購單數量時，系統要求填寫差異原因，批次數量以**實際入庫數量**為準，採購單剩餘待入庫數量保留（可手動結案）。

- **UJ-2. 倉管小惠在客戶催貨時快速定位商品。**
  - **Persona + context:** 倉管小惠，被業務拜託確認「那個藍色料號還有沒有、在哪」。
  - **Entry state:** 已登入，從桌面開啟首頁的「庫存查詢」。
  - **Path:** ① 輸入商品名稱或商品編號（支援模糊比對）→ ② 結果清單列出各倉庫的**在手量**與**可用量**並標示位置 → ③ 點進任一筆看見該批次的入庫時間與剩餘量。
  - **Climax:** 她在 10 秒內回覆業務「南港倉還有 30 件，A-03 位置」。
  - **Resolution:** 若數量不足，畫面顯示其他倉可用量並提供「建立調貨單」入口。

- **UJ-3. 業務小美替客戶報價，卻沒有賠錢。**
  - **Persona + context:** 業務小美，負責中型客戶報單，手中有一張客戶的採購需求。
  - **Entry state:** 已登入（銷售角色），開啟「新增銷貨單」。
  - **Path:** ① 從商品查詢結果多選商品加入同一張銷貨單 → ② 選擇客戶、填數量與單價並設定折扣 → ③ 系統即時顯示折後金額、預估成本與毛利（含毛利佔比）→ ④ 與客戶確認後過帳。
  - **Climax:** 畫面顯示「折後總額 NT$48,600，預估毛利 NT$9,720（20.0%）」，小美確認折扣不會讓這單虧損。
  - **Resolution:** 單據過帳，系統建立**配置量**並認列收入與成本，倉管收到出貨待辦。
  - **Edge case:** 折扣讓毛利低於門檻（預設 10%），系統跳出警告但允許繼續，並要求填寫原因。

- **UJ-4. 採購大明在一張清單上看到所有快斷貨的商品。**
  - **Persona + context:** 採購大明，每週一早上要決定這週補哪些貨。
  - **Entry state:** 已登入（採購角色），開啟「庫存水位警示」。
  - **Path:** ① 看到所有已設定水位且**供給量**（可用量＋已下單未入庫＋在途）低於水位的商品（依缺口排序）→ ② 選取數筆商品 → ③ 一鍵產生採購單，帶入商品、主供應商與建議補貨量 → ④ 填入預估單價與數量後送出。
  - **Climax:** 清單轉為一張採購單，大明省下逐項查詢與重複輸入的時間。
  - **Resolution:** 採購單送出，倉管收到待入庫清單；該商品在供給量補足前**不再**出現在警示清單。
  - **Edge case:** 某商品已有一張在途的調貨單，警示清單不再重複建議補貨，只標示「在途 N 件」。

- **UJ-5. 倉管跨倉調貨，讓客戶不等補貨。**
  - **Persona + context:** 倉管阿哲，接到業務的調貨需求，要把中港倉的貨調到南港倉。
  - **Entry state:** 已登入，在銷貨單或庫存查詢畫面發現南港倉不足、中港倉有餘。
  - **Path:** ① 建立「調貨單」，指定來源倉、目的地倉、商品、批次與數量 → ② 確認出庫後，數量離開來源倉並進入「在途」→ ③ 貨品到達後，目的地倉執行「收貨」確認，數量回到可用量。
  - **Climax:** 客戶在南港倉拿到貨，商品沒有重複出貨。
  - **Resolution:** 調貨單狀態為「已收貨」，兩倉庫存一致，批次身分沿用原批次。
  - **Edge case:** 抵達時實收數量少於調出數量，系統允許部分收貨並標註「短缺」，短缺數量由**調整單**承接（見 FR-30），差額留下稽核紀錄。

- **UJ-6. 會計小陳在月底對毛利。**
  - **Persona + context:** 會計小陳，月底需要出成本與毛利報表給老闆。
  - **Entry state:** 已登入（會計角色），開啟「報表」。
  - **Path:** ① 選擇報表類型（庫存結構、銷貨毛利）與期間 → ② 篩選倉庫與商品 → ③ 匯出 CSV 或列印。
  - **Climax:** 報表上的每一筆毛利都能點回原始銷貨單與該批次的入庫成本，且報表標明「未稅、含批次進貨單價、不含運費關稅」。
  - **Resolution:** 小陳匯出報表，核對無誤。

- **UJ-7. 倉管阿哲用盤點找出帳實不符的位置。** *[加值項]*
  - **Persona + context:** 倉管阿哲，主管要求每月抽盤，他不想重做整張紙本表。
  - **Entry state:** 已登入，在「盤點」畫面選擇要盤的倉庫、位置或商品範圍。
  - **Path:** ① 系統以**盤點開始時點**的帳面帶出品項清單，並凍結該範圍的異動 → ② 阿哲逐項輸入實盤數量 → ③ 有差異的項目要求填寫原因 → ④ 送出盤點結果，差異由**調整單**承接（FR-30）。
  - **Climax:** 畫面顯示「盤點完成：18 項中 2 項有差異，合計 −3，已產生差異調整待管理者核准」。
  - **Resolution:** 帳面與實盤的差異被記錄且可追溯，盤點不再是靠記憶的儀式。
  - **Edge case:** 盤點期間有人想對同一位置入庫，系統擋下並提示「該位置盤點中」，盤點結束後自動解除凍結。

- **UJ-8. 管理者設定水位與商品主檔。** *[加值項]*
  - **Persona + context:** 管理者老陳，每季調整一次商品資料與補貨水位。
  - **Entry state:** 已登入（管理員角色），開啟「商品主檔」。
  - **Path:** ① 建立新商品，設定名稱、單位、主供應商與預估毛利目標 → ② 首次進貨後系統依實際入庫單價反推建議售價 → ③ 依「商品 × 倉庫」設定安全庫存水位與交期天數 → ④ 儲存。
  - **Climax:** 畫面顯示「商品 IT-000123 建議售價 NT$60（目標毛利率 25%），南港倉水位 50」。
  - **Resolution:** 水位設定完成，該商品自下次查詢起納入警示清單。

- **UJ-9. 倉管報廢一批破損品，不動手改數字。**
  - **Persona + context:** 倉管阿哲，搬運時摔壞兩箱貨。
  - **Entry state:** 已登入，在庫存查詢找到該批次。
  - **Path:** ① 選擇「庫存調整／報廢」並指定批次、數量、原因（損壞）→ ② 說明文字 → ③ 送出，管理員核准。
  - **Climax:** 畫面顯示「調整單 AD-20260415-001 送審：批次 B-20260415-001 報廢 2，庫存已標記待核准」。
  - **Resolution:** 核准後庫存扣減、毛利不受影響（成本從庫存移除），稽核軌跡完整。

## 3. Glossary

本文件所有條目一律使用下列用語，不得出現同義詞。**凡文件內出現但未收錄於此的領域名詞，視為文件缺陷。**

- **商品（Item）** — 可被買賣與管理的最小品項單位。具有系統自動生成的**商品編號**（格式 `IT-` + 6 位數字流水 [ASSUMPTION: A11]）、名稱、單位、**建議售價**與**預估毛利**目標。一個商品可對應多個**批次**，並可對應多個**供應商**。
- **批次（Batch）** — 同一商品因不同**入庫單**或進貨時間而形成的可獨立追蹤單位。**於入庫單過帳時建立**，編號格式 `B-YYYYMMDD-NNN`（N = 當日流水，3 位）。屬性包含**批次編號**、商品、來源**採購單**、供應商、**實際入庫單價**、批次數量、入庫日期、選填**有效期限**。批次可跨多個庫存位置。
- **供應商（Supplier）** — 商品的來源單位。屬性包含**統一編號**、公司名稱、聯絡人、電話。同一商品可有多個供應商，其中一個可標為**主供應商**。
- **客戶（Customer）** — 銷貨與寄貨的對象。屬性包含**客戶名稱**（唯一）、聯絡人、電話。v1 採**最小客戶主檔**（FR-32）。
- **倉庫（Warehouse）** — 持有庫存的地點。系統支援**多倉庫**設定。
- **庫存位置（Location）** — 倉庫內部的儲存格位或區域，**一對多**對應倉庫。商品存放與移動的最小顆粒。
- **在途位置（TRANSIT）** — **虛擬位置**，不屬於任何實體倉庫，用來承載跨倉調貨中「已離開來源倉、尚未抵達目的地倉」的數量。**在途量不計入任何實體倉的可用量與在手量，但計入系統層的總餘額**（見 §4.7 恆等式）。
- **在手量（On Hand）** — 實際登記在該倉庫／位置上的數量，**包含已被單據配置但尚未出貨的數量**。由實體異動帳推導。
- **可用量（Available）** — 在手量扣除**配置量**後、可以立即再賣出的數量。**水位警示與可否成交一律依可用量判斷，不依在手量。**
- **配置量（Allocated）** — 已被**已過帳但尚未出貨**的**銷貨單與寄貨單**占用的數量。以配置明細（allocation）存放，**不寫入實體異動帳**。**跨倉調貨不計入配置量**（移出時數量即離開來源倉進入在途，不存在「已配置待出庫」狀態）。
- **配置（Allocation）** — 一筆「哪張單據、哪個批次、哪個位置、占用多少量」的明細。銷貨單或寄貨單**過帳時**建立，倉管**領用出庫時**解除。
- **在途量（In Transit）** — 位於**在途位置**的數量。
- **安全庫存水位（Reorder Point）** — 以「**商品 × 倉庫**」為單位設定的補貨觸發點，計算基準為**供給量**。**v1 為人工設定值，不依用量自動計算** [ASSUMPTION: A15]。
- **供給量（Supply）** — 某商品在某倉的總供給 = **可用量 ＋ 已下單未入庫數量 ＋ 在途量**。水位警示以此對比水位，避免重複下單。
- **建議補貨量** — 缺口量（`水位 − 供給量`）加上前置期需求（`平均日用量 × 交期天數`），再依選填的**最小下單量**與**包裝倍數**向上調整。缺前置期資料時退回「缺口量」。
- **缺口量** — `水位 − 供給量`；大於 0 即為需補貨。
- **採購單（PO）** — 向供應商下單的單據，編號格式 `PO-YYYYMMDD-NNN`。含供應商、**預估單價**、**總價**、**訂購數量**、預計到貨日期，狀態為「草稿／已送出／部分入庫／已入庫／已結案／已取消」。**採購單的單價為預估值，不構成成本依據。**
- **訂購數量 / 已入庫數量 / 待入庫數量** — 同一採購單行的三個量：`待入庫數量 = 訂購數量 − 已入庫數量`。
- **入庫單（GRN）** — 記載商品實際進入倉庫與庫存位置的單據，編號格式 `GR-YYYYMMDD-NNN`。承載**入庫數量**、**實際入庫單價**、**入庫人員**、**入庫日期**、庫存位置。**入庫單過帳時建立批次。**
- **銷貨單（SO）** — 對外銷售的單據，編號格式 `SO-YYYYMMDD-NNN`。**銷貨單是收入與毛利的唯一認列來源**，由銷售角色建立。含**客戶**、多項商品、數量、單價、折扣、折後金額、**銷貨人員**、**銷貨日期**、**銷貨金額**。
- **寄貨單（SH）** — 將商品寄給客戶保管或使用、暫不認列收入的單據，編號格式 `SH-YYYYMMDD-NNN`。含客戶、商品、數量、日期、經辦人，狀態為「草稿／已確認（占用可用量、待寄出）／已寄出（已離開倉庫）／已收回入庫／已轉銷貨／已退寄」。
- **調貨單（TO）** — 將商品由來源倉移往目的地倉的單據，編號格式 `TO-YYYYMMDD-NNN`。狀態為「草稿 → 在途 → 已收貨（可標記短缺）」。**移出不建立配置量**：數量離開來源倉後即進入**在途位置**。
- **反向單據（RT）** — 沖銷已過帳單據的單據，編號格式 `RT-YYYYMMDD-NNN`。用於銷貨退貨與供應商退貨，會回溯影響庫存、成本與毛利。**已過帳單據不可修改，只能以反向單據更正。**
- **調整單（AD）** — 承接庫存數量增減但非正常進銷的單據，編號格式 `AD-YYYYMMDD-NNN`。用於**報廢損壞、盤點差異、調貨短缺、內部領用**。調整單是數量守恆的最後一塊拼圖。
- **領用（出庫作業）** — 倉管人員將商品實際移出庫存的動作，**必須關聯一張既有單據**：銷貨單（用途＝**銷貨**）、寄貨單（用途＝**客戶寄貨**）或調整單（用途＝**報廢／內部領用**）。領用本身**不認列收入、不建立銷貨單**。
- **領用用途代碼** — 固定代碼集：**銷貨、客戶寄貨、報廢損壞、樣品試用、內部領用、盤點調整**。領用用途必須與所關聯的單據類型相符。
- **移轉（Transfer）** — 在不離開庫存系統的前提下改變商品的庫存位置；同倉移轉即時完成，跨倉移轉產生**調貨單**。
- **盤點（Stocktake）** — 對指定倉庫、位置或**商品範圍**實際清點並與帳面數量比對的作業。**盤點基準為盤點開始時點的帳面**，盤點期間凍結該範圍的異動。產出**差異調整**並由**調整單**承接。
- **盤點差異（正負號定義）** — `差異 = 實盤數量 − 帳面數量`。**正數為盤盈（增加庫存，以最近進貨單價認列成本），負數為盤虧（扣減庫存，產生調整單）。**
- **成本價（Cost）** — 該批次的**實際入庫單價**，v1 以**先進先出（FIFO）** 取用 [ASSUMPTION: A4]。成本**不包含**運費、關稅、稅費與包材 [NON-GOAL for MVP]。
- **FIFO 規格** — 排序鍵為**批次入庫日期**，同日以**批次編號流水**排序；適用層級為**商品層級跨位置**（同一商品的所有位置共用一個 FIFO 佇列）。指定來源位置出庫時，**先扣該位置**，不足時提示跨位置補足並需使用者確認。
- **成本快照（Cost Snapshot）** — 銷貨單或寄貨單過帳時寫入每行的成本快照（批次、數量、單價、金額），之後批次單價或成本規則變動**不回溯影響歷史毛利**。
- **成本取用明細（Cost Consumption）** — 記錄每一次出貨取用了哪個批次、多少數量、多少成本的明細表，是 FR-17 成本展開與 FIFO 正確性的基礎。
- **毛利（Gross Margin）** — 折後售價減成本價。**毛利額與毛利率**分開顯示，毛利率 = 毛利額 ÷ 折後售價（折後售價為 0 時顯示「—」）。
- **毛利口徑** — v1 毛利為**未稅**、以**批次實際進貨單價**為基礎、**不含**運費／關稅／稅費／包材／折扣讓利。報表上必須標註此口徑。
- **毛利門檻** — 低於此毛利率時銷貨單顯示警告。預設 10%，為**全公司單一值**，可由管理者設定 [ASSUMPTION: A12]。與「商品預估毛利目標」（商品級，用於對照達成率）是兩套不同用途的值。
- **建議售價（RSP）** — 依**最近一次實際入庫單價**與預估毛利目標反推：`建議售價 = 最近實際入庫單價 ÷ (1 − 預估毛利率目標)`，向上取整至整數；尚無進貨紀錄時留空並顯示「待首次進貨」。
- **操作紀錄（Audit Trail）** — 每一筆庫存異動與單據狀態變更的**不可刪除**紀錄，記錄操作人員、時間、動作、數量、庫存位置、原因。**即時寫入、永久可查。**
- **帳密（Credentials）** — 帳號與其密碼。密碼僅以**雜湊**儲存，**任何情況下不得以明文出現在投影片、原始碼、對話紀錄或憑證檔中**。外部工具若需存取資料庫，應使用**最小權限的獨立帳號**；v1 不實作權杖（token）機制 [NON-GOAL for MVP]。
- **角色（Role）** — 權限群組，v1 固定為**倉管、採購、銷售、會計、管理員**五種 [ASSUMPTION: A8]。
- **商品組合** — 一組常用商品的集合，可於新銷貨單一鍵帶入 [ASSUMPTION: A13]。

## 4. Features

### 4.1 帳號、角色與操作紀錄

**Description：** 系統需要辨識「誰做了什麼」，並限制各職能只能做自己的事。倉管不該能改成本價，銷售不該能直接改庫存餘額。所有單據與庫存異動都必須留下不可刪除的**操作紀錄**，這是後續盤點差異能夠被解釋的基礎。

**Functional Requirements:**

#### FR-1: 以帳密登入與登出

使用者可使用帳號與密碼登入系統，登入前無法存取任何業務功能；可隨時登出。登入失敗時不得透露帳號是否存在。

**Consequences (testable):**
- 密碼錯誤時回應固定訊息「帳號或密碼錯誤」，且連續 5 次失敗鎖定該帳號 15 分鐘，鎖定自動於 15 分鐘後解除；鎖定與解除事件寫入**操作紀錄**。
- 未登入狀態存取任何業務頁面，導向登入頁。
- 密碼在資料庫中以單向雜湊儲存（bcrypt 或 argon2），任何介面與日誌都不顯示明文密碼 [ASSUMPTION: A5]。
- 密碼長度至少 8 字元，且不得與帳號相同；首次登入須變更初始密碼 [ASSUMPTION: A5]。

#### FR-2: 依角色限制功能與資料

系統依**角色**控制功能可用性與資料可見範圍；越權存取被拒絕且不洩漏該筆資料內容。權限矩陣如下（✅ 可操作／👁 唯讀／✖ 不可見）：

- 倉管角色可見全部倉庫的庫存，但不可修改成本價與毛利設定。
- 會計角色可唯讀所有單據與報表，不可建立或過帳單據。
- 採購角色的銷貨查詢結果不含客戶名稱欄位。
- 權限判斷於伺服器端執行，隱藏前端按鈕不算通過。

#### FR-26: 帳號與角色管理

管理員可建立帳號、指派**角色**、停用帳號與重設密碼；被停用帳號不得登入。**初始管理員帳號由部署時的種子資料建立**（見 §6.1 種子資料）。

**Consequences (testable):**
- 新建帳號必須指派五種角色之一，未指派者不得登入。
- 停用帳號後，既有登入 session 於下次請求時失效。
- 帳號的建立、停用與角色變更寫入**操作紀錄**。
- 管理員不得停用自己（避免系統被鎖死）。
- 重設密碼後舊密碼立即失效，且發給使用者的初始密碼為一次性、首次登入須變更。

#### FR-3: 記錄不可刪除的操作紀錄

每一筆庫存異動與單據狀態變更，系統**於同一資料庫交易內**寫入**操作紀錄**，包含操作人員、時間、單據或批次識別、數量、庫存位置、原因。

**Consequences (testable):**
- 庫存異動過帳與操作紀錄寫入為同一交易：異動成功則紀錄存在，異動回滾則紀錄不留下。
- 任一筆庫存數字的變動，**任何時間點**皆可查出對應操作紀錄，永久保留。
- 操作紀錄不可透過任何介面刪除或修改。
- 紀錄同一筆單據的重複嘗試過帳（第二次）會被拒絕並留下拒絕紀錄。

**Feature-specific NFRs:**
- 登入與查詢操作不得洩漏密碼或權杖明文至伺服器日誌。
- 操作紀錄保存期限為「永久（不刪除）」；課程階段不設保存期 [ASSUMPTION: A5]。

### 4.2 商品、批次、供應商與客戶主檔

**Description：** 所有後續流程都以**商品**與**批次**為基礎。批次是成本與追蹤的最小單位。**供應商**是商品的來源（多對多，可設主供應商）；**客戶**是銷售與寄貨的對象。

**Functional Requirements:**

#### FR-4: 建立與維護商品主檔

管理者可建立**商品**，系統自動產生唯一的**商品編號**（序號流水）[ASSUMPTION: A11]，並記錄名稱、單位、**建議售價**、**預估毛利**目標與關聯供應商。

**Consequences (testable):**
- 新增商品後，商品編號依流水規則自動產生且不重複。
- 同一供應商可關聯多個商品，同一商品可有多個供應商，其中一個為**主供應商**。
- 商品在被任何單據引用後不可刪除，只能停用。
- 商品編號格式為 `IT-` + 6 位數字流水。
- 每個商品在 v1 僅使用**單一單位**（不支援箱／盒換算）[ASSUMPTION: A16]。

#### FR-5: 維護批次資訊

**入庫單過帳時**由系統建立**批次**，記錄**批次編號**（帶入該入庫單日期）、商品、來源採購單、供應商、**實際入庫單價**、批次數量、入庫日期與選填有效期限；批次可查詢、查閱剩餘量與其成本。

**批次層等式（統一符號）：**
`批次數量 = 已出庫量（銷貨出貨／寄出／報廢） + 已盤虧報廢量 + 批次剩餘量`

- **批次剩餘量** = 批次數量 − 上列兩項，代表仍存在於某位置的數量（可能分散於多個位置，**包含在途位置**）。
- **移轉不改變批次剩餘量**（來源位置 −N、在途位置 +N），故跨倉移出不列為扣減項。
- **批次可用量** = 批次剩餘量 − 該批次的**配置量**。

**Consequences (testable):**
- 批次編號唯一，格式為 `B-YYYYMMDD-NNN`（N 為當日 3 位流水），日期為入庫單日期。
- 批次剩餘量依上式計算，且其明細可逐筆對應到異動帳的每一筆。
- 每個批次可查出其對應銷貨單的成本取用結果（FIFO 順序），取用明細存放於**成本取用明細**。
- 同一批次可同時存在於多個庫存位置；**所有位置（含在途位置）的數量加總等於批次剩餘量**；實體倉（不含在途）加總 = 批次剩餘量 − 在途量。
- 批次可設定**有效期限**；已設定有效期限的批次在查詢與警示清單中可依到期日排序 [ASSUMPTION: A17]。

#### FR-6: 依名稱或編號查詢商品

使用者可依商品名稱（模糊比對）、商品編號、供應商或庫存位置查詢商品，結果顯示各倉**在手量**與**可用量**。

**Consequences (testable):**
- 輸入部分名稱即能列出候項（回傳結果上限 50 筆，可分頁）。
- 每筆結果同時顯示在手量與可用量，且兩者不一致時明確標示差額來源（**配置量**、**在途量**、**盤點差異**）。
- 結果顯示該商品**最近一次採購日期**（取最新批次的入庫日期）。
- 查詢結果的三個數量欄位（在手量／可用量／在途量）與 FR-12、FR-24 採用**同一組定義與取數時點**（即時）[DECISION]。

#### FR-7: 設定建議售價與預估毛利

管理者可對商品設定**預估毛利**目標；系統依**最近一次實際入庫單價**反推**建議售價**，銷售在報價時可參考；管理者亦可直接填寫建議售價覆寫。

**Consequences (testable):**
- 建議售價 = 最近實際入庫單價 ÷ (1 − 預估毛利率目標)，向上取整至整數；商品尚無進貨紀錄時欄位留空並顯示「待首次進貨」。
- 覆寫建議售價時，系統仍保留預估毛利目標值供 FR-17 對照，並記錄覆寫前的反推值。
- 覆寫建議售價不會改動既有批次的**實際入庫單價**與成本。
- 所有金額為**未稅**金額 [DECISION]。

### 4.3 庫存管理

**Description：** 庫存是整個系統的中心。**倉庫**與**庫存位置**構成存放階層；**入庫**、**領用（出庫作業）**、**移轉**是三種實體異動；**調整**承接所有非正常進銷的增減；**盤點**負責讓帳面回到真實。判斷「能不能賣」一律用**可用量**而不是在手量。

**Functional Requirements:**

#### FR-8: 維護多倉庫與庫存位置

管理者可建立、停用**倉庫**與其下的**庫存位置**；位置以代碼＋名稱表示，關聯唯一倉庫。停用前必須為零庫存。

**Consequences (testable):**
- 同一位置代碼在不同倉庫可重複，同一倉庫內不可重複。
- 有庫存的倉庫或位置不可停用，系統擋下並列出剩餘數量。
- 每筆庫存數字都必然對應到一個「倉庫 + 位置」（或**在途位置**）。

#### FR-9: 入庫

倉管人員可對**採購單**執行**入庫**（分批入庫），或由管理員建立手動入庫單；入庫需指定商品、**數量**、**實際入庫單價**、**庫存位置**、日期與人員，過帳後由系統建立**批次**並立即增加庫存。

**Consequences (testable):**
- 對採購單入庫時，入庫數量不得大於該採購單行的**待入庫數量**（`訂購數量 − 已入庫數量`）。
- 手動入庫單**僅限管理員建立**，且必須填寫原因；手動入庫會建立批次並以填入的實際單價作為成本依據。
- 入庫數量須大於 0；入庫後該位置的在庫量即時等於原值 + 本次入庫數量。
- 入庫紀錄包含人員、日期、位置、數量與實際單價，且不可刪除。
- **入庫單過帳時建立批次**，批次編號帶入該入庫單日期；一張採購單可對應多張入庫單、產生多個批次 [DECISION]。

#### FR-27: 以庫存位置為入口的入庫

倉管人員可輸入**庫存位置**代碼，直接檢視該位置現有的品項與數量，並對指定品項輸入數量完成入庫。

**Consequences (testable):**
- 輸入不存在的位置代碼時拒絕，並列出該倉庫的可用位置清單。
- 畫面同時顯示該位置每個品項的帳面數量與其批次資訊。
- 由位置入口完成的入庫與 FR-9 產生相同格式的入庫單與批次。

#### FR-10: 領用（出庫作業）

倉管人員可執行**領用**，**必須關聯一張既有單據**：銷貨單（用途＝**銷貨**）、寄貨單（用途＝**客戶寄貨**）或調整單（用途＝**報廢／內部領用**）。領用需指定商品、數量、來源位置與對應單據，庫存即時扣減。

**Consequences (testable):**
- 領用數量不得大於該位置的**可用量**，否則拒絕並顯示可用量。
- 領用必須帶入來源單據編號，**無單據不可領用**；領用**不建立銷貨單、不認列收入**。
- 用途由所關聯的單據類型決定，不可手動選擇與單據不符的用途。
- 領用後在來源單據上留下出庫明細與時間戳，**操作紀錄**記錄人員、日期、位置、數量。
- 同一銷貨單可分多次領用，累計領用量不得超過該單的配置量。
- 領用後**解除對應配置量**，可用量回升。
- 領用用途僅限固定代碼集：**銷貨、客戶寄貨、報廢損壞、樣品試用、內部領用、盤點調整**。

#### FR-11: 庫存移轉

倉管人員可將商品自一個**庫存位置**移至同一倉庫的另一位置，或跨**倉庫**移轉；跨倉移轉產生**調貨單**，數量自來源倉離開後進入**在途位置**，抵達後由目的地倉收貨確認。

**Consequences (testable):**
- 同倉移轉：移出與移入在同一筆紀錄內完成，總量守恆，在手量不變。
- 跨倉移轉：移出時**在手量與可用量同步扣減**，數量進入**在途位置**；在途期間不計入任何實體倉的可用量與在手量，但計入系統層總餘額。
- 跨倉移轉**必須指定批次**；批次身分沿用原批次，目的地倉不新建批次。
- 抵達時**實收數量少於調出數量**，允許部分收貨並標註「短缺」；短缺數量由**調整單**承接（FR-30），並留下**操作紀錄** [DECISION]。
- 調貨單狀態依序為：草稿 → 在途 → 已收貨（可標記短缺）。

#### FR-12: 快速定位商品與庫存

倉管人員可輸入商品名稱或**商品編號**，即時取得該商品在各倉庫、位置的**位置**、**在手量**與**可用量**，並可由此直接發起**入庫**。

**Consequences (testable):**
- 查詢結果在 2 秒內回應（資料量基準見 §4.8 效能條款）。
- 結果依**商品層級可用量合計**由大到小排序；同商品的多個位置以位置代碼排序。
- 可由結果一鍵建立**入庫單**並帶入商品與目標位置。
- 可由結果一鍵建立**領用（出庫）**並帶入商品；來源位置由使用者指定，未指定時**依 FIFO 順序自動挑選**並於畫面顯示所挑的位置 [DECISION]。
- 當目前位置可用量不足時，結果顯示其他倉可用量並提供「建立調貨單」入口（與 FR-15 同一入口，發起角色依 §4.1 權限矩陣）[DECISION]。

#### FR-13: 盤點與差異調整 *[加值項：研究導向，簡報未要求]*

倉管人員可對指定倉庫、位置或**商品範圍**執行**盤點**；**盤點基準為盤點開始時點的帳面數量**，盤點期間**凍結**該範圍的異動；實盤結果產生**盤點差異**（`實盤 − 帳面`）並由**調整單**承接。

**Consequences (testable):**
- 盤點開始時系統凍結該範圍；凍結期間的入庫、出庫、移轉請求被拒絕並提示「該範圍盤點中」，盤點結束後自動解除。
- 盤點差異量大於 0 時必填原因（帳實不符／遺失／誤植／退貨）。
- **盤盈**（差異 > 0）以該商品**最近一次實際入庫單價**認列成本；若該商品無任何進貨紀錄，須由管理員手動輸入認列成本。
- **盤虧**（差異 < 0）依 **FIFO 順序**自最早的批次扣減，並產生**調整單**。
- 盤點完成後，該範圍的帳面數量等於實盤數量，且差異可由**操作紀錄**追溯。
- 盤點**不得使在手量低於既有配置量**；若有配置未出貨，該品項標示「需先結清配置」且不自動調整。
- 差異需管理者核准後才調整帳面 [ASSUMPTION: A14]。
- 盤點支援**商品範圍盤點**（盤某商品在各倉的數量），不限於整倉或整位置。
- **降級路徑**：若課程評分未要求盤點，可降級為「差異登記」（僅記錄差額與原因，不做盤點工作單與凍結）。

#### FR-31: 負庫存與超賣的全域防護

**所有**會影響庫存的異動路徑（領用出庫、跨倉調出、盤點調整、調整單、寄出）皆受同一道全域約束：**異動完成後，任何位置、任何批次的可用量不得為負**。

**Consequences (testable):**
- 任一異動後若將造成負可用量，系統拒絕該異動並顯示各位置的可用量缺口。
- 盤點若將使在手量低於既有配置量，該品項拒絕自動調整並提示「需先結清配置」。
- 盤點、調整、調出與領用的同時性以列鎖或版本欄位處理，測試期間超賣次數為 0（SM-9）。
- 負庫存防護不因角色而放寬；管理員亦不可建立負可用量（若需盤盈，必須走 FR-13 盤盈並以調整單認列成本）。

### 4.4 銷售管理

**Description：** 銷售是唯一直接產生收入與毛利的流程。**銷貨單是收入與毛利的唯一認列來源**；倉管的**領用**只負責出貨，不建立銷貨單。

**Functional Requirements:**

#### FR-14: 建立含多品項的銷貨單

銷售人員可建立**銷貨單**並加入多項商品，每項含數量與單價；單據需記錄**客戶**、**銷貨人員**、**銷貨日期**與**銷貨金額**，過帳後**認列收入與成本並建立配置量**（庫存實體仍留在倉庫，待倉管領用）。

**Consequences (testable):**
- 單據至少一項商品方可過帳；**客戶為必填**（FR-32 最小客戶主檔）。
- 可由商品查詢結果**多選後一次加入同一張銷貨單**，加入時自動帶入各倉可用量並標示缺口。
- 提供**商品組合**（常用商品組）快速套用功能，可將一組商品儲存為組合並於新銷貨單一鍵帶入 [ASSUMPTION: A13]。
- 過帳時各項商品依 **FIFO** 取得成本（批次**實際入庫單價**），並**寫入成本快照**與**成本取用明細** [DECISION]。
- 過帳時**建立配置量**（可用量立即下降、在手量不變）；倉管領用後**解除配置**（在手量下降）。
- 銷貨單過帳後不可修改；更正須以**反向單據**處理（FR-29）。
- 銷貨金額與毛利**只在此處認列一次**；倉管領用不得另建銷貨單（FR-10）。

#### FR-15: 交易前檢查可用量

建立銷貨單時，系統即時顯示每項商品在各倉的**可用量**並阻擋超過可用量的下單。

**Consequences (testable):**
- 設定的數量超過任一來源倉可用量時，該行標示不足並阻擋**過帳**（草稿可存在但不可過帳）[DECISION]。
- 提示訊息包含「可用量 / 需求數量 / 缺口」。
- 若其他倉庫有貨，結果中顯示其他倉的可用量並提供「建立調貨單」入口（與 FR-12 同一入口）。
- 過帳時以**列鎖或版本欄位**防止兩個銷貨單同時讀到同一可用量而重複出貨（超賣）[DECISION]。

#### FR-16: 折扣設定與金額試算

銷貨單可設定單品折扣或整單折扣（百分比或固定金額），系統即時計算折後金額。

**計算順序（唯一）**：
1. 行小計 = 單價 × 數量
2. 行折後 = 行小計 × (1 − 單品折扣率) − 單品固定折扣
3. 整單固定金額折扣依**各行折後金額比例分攤**至各行，四捨五入至小數兩位，**尾差歸最後一行** [DECISION]
4. 整單百分比折扣依序套用於各行
5. 單據折後總額 = Σ各行最終折後金額

**Consequences (testable):**
- 依上述順序計算，畫面顯示完整計算過程。
- 分攤後各行折後金額加總等於單據折後總額（尾差歸最後一行），故行層毛利加總等於單據毛利額。
- 折扣後毛利率低於**毛利門檻**（預設 10%，全公司單一值，可由管理者設定 [ASSUMPTION: A12]）時顯示警告，要求填寫原因後方可過帳。
- 折後金額為 0 時，毛利率顯示「—」而非錯誤。

#### FR-17: 毛利試算

每張銷貨單顯示**毛利額**與**毛利率**，並對照商品的**預估毛利**目標標示是否達成。

**Consequences (testable):**
- 毛利額 = 折後金額 − 成本額；毛利率 = 毛利額 ÷ 折後金額（分母為 0 時顯示「—」）。
- 成本額可展開檢視**成本取用明細**（每筆取用哪個批次、數量、單價）。
- 成本**不包含**運費、關稅、稅費與包材 [NON-GOAL for MVP]；報表須標註**毛利口徑**。
- 毛利率低於預估毛利目標時明確標示差異。
- 已過帳單據顯示的是**成本快照**，不因後續批次或規則變動而改變。

#### FR-18: 建立調貨單

當目的地倉無貨而其他倉有貨時，使用者可建立**調貨單**，指定來源倉、目的地倉、商品、**批次**與數量；調貨單一經確認即產生在途量。

**Consequences (testable):**
- 調出數量不得大於來源倉可用量。
- 必須指定批次與來源位置；批次剩餘量須足以支應調出數量。
- 調貨單狀態機為「草稿 → 在途 → 已收貨（可標記短缺）」，每個狀態轉換記錄時間戳 [DECISION]。
- 同一商品存在多張未完成調貨單時，畫面提示但允許建立。
- 調貨單可記錄**需求來源**（例如「因南港倉缺貨」），供調撥原因分析 [ASSUMPTION: A18]。

#### FR-19: 查詢銷貨紀錄

使用者可依期間、**銷貨人員**、商品、**客戶**或倉庫查詢**銷貨紀錄**，並檢視每筆的毛利與成本來源。

**Consequences (testable):**
- 每筆銷貨紀錄可由金額追溯至原始銷貨單、其成本批次與入庫紀錄。
- 結果可依金額、日期、數量排序與匯出。
- 結果顯示該筆銷貨的出貨進度（已配置 / 已領用 / 未領用數量）。

#### FR-29: 反向單據（退貨與沖銷）

已過帳的單據不得修改；需以**反向單據**更正，冲銷後原單據狀態標示為「已沖銷」。

**Consequences (testable):**
- 銷貨單可建立**反向單據**（客戶退貨）：**回補庫存至原批次**（成本不變，並記錄「退貨回補」）、**沖回收入與毛利**。
- 入庫單可建立**反向單據**（供應商退貨）：扣回庫存與成本，沖回該批次的毛利影響。
- 反向單據本身亦不可修改，僅能再被反向單據沖銷。
- 反向單據過帳後，相關報表的毛利合計維持等於各銷貨單毛利額合計之原則（已沖銷者以負數計入）。

### 4.5 採購管理

**Description：** 採購的起點是**安全庫存水位**。低於水位不應靠人巡檢發現，而應由系統主動列出；**已經在路上的貨不應再被提醒**。採購單把補貨意圖變成**批次**的來源，但**成本**一律以入庫時的**實際入庫單價**為準。

**Functional Requirements:**

#### FR-20: 維護供應商資料

管理者可建立與維護**供應商**：**統一編號**、公司名稱、聯絡人、電話，並將供應商關聯至商品（可設**主供應商**）。

**Consequences (testable):**
- 統一編號為必填且唯一（8 位數字）；公司名稱必填。
- 同一供應商可掛多個商品；同一商品可有多個供應商，其中一個為**主供應商**。
- 供應商基本資料變更保留修改紀錄。

#### FR-21: 設定商品安全庫存水位

管理者可為**每一個商品 × 每一個倉庫**設定**安全庫存水位**、**交期天數**與**最小下單量**；系統以**供給量**為基準比對。

**Consequences (testable):**
- 水位以「商品 × 倉庫」為單位設定；同一商品在不同倉可設定不同水位。
- 比較基準為**供給量**（可用量 ＋ 已下單未入庫數量 ＋ 在途量）；在手量高但已被大量配置的商品仍會觸發警示。
- **僅已設定水位的商品 × 倉庫**列入警示清單 [DECISION]。
- 交期天數與最小下單量為選填；未設定時建議補貨量退回「缺口量」。

#### FR-22: 庫存水位警示清單

系統列出所有**供給量**低於水位的商品（僅含已設定水位者），依缺口量排序，並可由清單批次產生**採購單**。

**Consequences (testable):**
- 清單顯示商品、倉庫、**主供應商**、在手量、可用量、已下單未入庫量、在途量、供給量、水位、缺口量與建議補貨量。
- **已下單未入庫或在途的商品不得重複建議補貨**，其供給量已含這些數量。
- 支援勾選多筆商品一次產生採購單，帶入商品與主供應商。
- 補貨入庫後，若供給量回到水位以上，下次查詢即不再出現。
- 建議補貨量 = 缺口量 ＋（平均日用量 × 交期天數），再依最小下單量與包裝倍數向上調整；未設定前置期資料時退回缺口量。

#### FR-23: 建立採購單

採購人員可建立**採購單**，含供應商、**預估單價**、**總價**、**訂購數量**與預計到貨日期；送出後成為倉管的待入庫依據。

**Consequences (testable):**
- 總價 = 預估單價 × 訂購數量，可手動覆寫但需填寫原因；**總價與預估單價僅供顯示，不構成成本依據** [DECISION]。
- 採購單狀態依序為：草稿 → 已送出 → 部分入庫 → 已入庫，另有**已結案**（部分到貨後手動結案）與**已取消**。
- 每行顯示三個量：**訂購數量、已入庫數量、待入庫數量**（`待入庫 = 訂購 − 已入庫`）。
- 一張採購單可對應多張入庫單、產生多個批次；入庫數量分配總和不得超過訂購數量。
- 成本**一律**取入庫時的**實際入庫單價**；實際單價與預估單價的差異需填寫原因。

### 4.6 寄貨與庫存調整

**Description：** **客戶寄貨**是與「銷貨」並列的領用用途，但**不認列收入**；它需要自己的單據、狀態與回收閉環。**調整單**則承接所有非正常進銷的數量增減（報廢、盤點差異、調貨短缺、內部領用），是數量守恆的最後一塊拼圖。

**Functional Requirements:**

#### FR-28: 寄貨單與寄回流程

倉管或銷售可建立**寄貨單**，指定客戶、商品、批次、數量、來源位置、日期與經辦人；寄出後占用可用量但**不認列收入**；貨品收回時可入庫或轉為**銷貨單**。

**Consequences (testable):**
- 寄貨單狀態為「寄出／已收回入庫／已轉銷貨／已退寄」，每次轉換記錄時間戳與人員。
- 寄貨單**確認時建立配置量**（在手量不變、可用量下降）；倉管執行**寄出**（領用出庫，FR-10）時才扣減在手量並將狀態改為「已寄出」。寄出期間該數量不可再售。
- 收回時可選擇入庫（回到指定位置，**沿用原批次**與原成本）或轉銷貨（建立銷貨單並認列收入與毛利）。
- 客戶退寄（貨回來但未成交）以「已退寄」結案，**不產生收入**，庫存回到原批次。
- 寄貨數量不得大於來源位置可用量。
- 提供**未結清寄貨清單**（依期間、客戶、經辦人），顯示尚未收回或轉銷的寄貨單與數量 [DECISION]。
- 寄貨紀錄可依期間、客戶、經辦人查詢。

#### FR-30: 庫存調整與報廢單

倉管可建立**調整單**，用於**報廢損壞、盤點差異、調貨短缺、樣品試用、內部領用**；調整單經管理員核准後才調整帳面。

**Consequences (testable):**
- 調整單狀態為「草稿／待核准／已核准／已否准」，核准前不影響庫存餘額。
- 調整類型為**增加**（盤盈）或**減少**（報廢、盤虧、短缺）；減少時依 **FIFO 順序**自最早的批次扣減。
- 每筆調整必填原因代碼（報廢損壞／盤點差異／調貨短缺／樣品試用／內部領用）與說明文字。
- 調整單核准與否准皆寫入**操作紀錄**。
- **調整單是數量守恆的閉環**：所有離開庫存卻無其他單據承接的數量都必須落在調整單上。

### 4.7 客戶主檔

**Description：** 自由文字的客戶名稱在實務上無法查詢（同一客戶三種寫法），也無法追蹤寄貨與未結清金額。v1 建立**最小客戶主檔**。

**Functional Requirements:**

#### FR-32: 最小客戶主檔

管理者或銷售可建立**客戶**（客戶名稱唯一、聯絡人、電話），於建立銷貨單或寄貨單時可選擇既有客戶，或輸入新名稱由系統即時建立（重名時提示可選既有客戶）。

**Consequences (testable):**
- 客戶名稱唯一；重複輸入時系統提示既有客戶而非產生第二筆。
- 客戶主檔的建立、修改留有修改紀錄。
- 客戶可於**反向單據**後停用；被任何單據引用的客戶不可刪除。
- 銷售查詢銷貨紀錄時可依客戶篩選 [ASSUMPTION: A7]。

### 4.8 報表與資料匯出

**Description：** 報表是「庫存結構」與「賺不賺錢」的唯一呈現方式。課程階段的報表重點是正確與可追溯，而非視覺華麗。*[加值項：研究導向，簡報未要求]*

**Functional Requirements:**

#### FR-24: 庫存結構報表

可產出各**倉庫**、各**庫存位置**、各商品的**在手量**、**可用量**與**在途量**報表。

**系統層恆等式（口徑定義）：**
`Σ所有位置餘額（含在途位置） = Σ入庫數量 − Σ出庫數量 + Σ盤盈數量 − Σ盤虧與報廢數量`
`實體倉合計 = Σ所有位置餘額 − 在途量`

- **在途量不計入實體倉合計**，於報表另列一行。
- **寄出量計入出庫**（離開庫存系統），與銷貨出庫同列但可區分。

**Consequences (testable):**
- 報表顯示上式等式的左右兩側數值，使用者可自行核對；系統另提供一條對帳查詢供開發期自我檢查。
- 報表可匯出 CSV，編碼為 UTF-8（含 BOM）以利 Excel 開啟。
- 報表顯示資料產生時間點；期間篩選解讀為「期末時點」的結存。
- 三個數量欄位（在手量／可用量／在途量）與 FR-6、FR-12 採用同一組定義。

#### FR-25: 銷貨與毛利報表

可產出銷貨與**毛利**報表，含**銷貨人員**、商品、數量、金額、成本與毛利。

**Consequences (testable):**
- 報表毛利合計等於各銷貨單毛利額合計（**反向單據以負數計入**）。
- 金額單位與四捨五入規則與銷貨單一致。
- 可依期間、倉庫、商品、銷貨人員、客戶篩選。
- 期間內未過帳的單據不計入報表，並於報表上標示統計區間。
- 報表標註**毛利口徑**（未稅、批次實際進貨單價基礎、不含運費關稅稅費包材）。

## 5. Non-Goals (Explicit)

- **不做 POS 收銀、會員、付款整合。**
- **不做電商平台串接或公開 API。** v1 僅提供內部介面。
- **不做生產製造、BOM、工單與排產。**
- **不做固定資產或設備維保管理。**
- **不做多公司／多組織（Multi-company）架構。** v1 為單一公司、多倉庫。
- **不做行動原生 App 與離線模式。**
- **不做多幣別、多時區與多語系介面。**
- **不做貨運物流商串接、運費分攤與跨倉運費歸屬**（v1 運費不進入成本）[NON-GOAL for MVP]。
- **不取代會計總帳系統**：只輸出成本與毛利資料供對外匯出。
- **不實作權杖（token）與外部工具的自動化存取機制**：v1 僅保留最小權限帳號原則 [NON-GOAL for MVP]。
- **不實作總成本分攤（運費、關稅、損耗）**：成本僅為實際入庫單價，毛利因此可能高估 [NON-GOAL for MVP]。
- **不做序號（Serial）管理與多單位換算**：批次以數量管理，商品以單一單位管理 [NON-GOAL for MVP]。

## 7. Success Metrics

**Primary**
- **SM-1**：附錄「與簡報來源的對照」表中標示為「覆蓋」的列，其對應驗收案例**通過率 ≥ 90%**（分母固定為該表「覆蓋」列數，不含「補強」與「加值項」列，也不以 FR 數量為分母）；驗收由非組員執行。Validates FR-4 ~ FR-23。
- **SM-2**：UJ-1 ~ UJ-9 九條情境可由**非組員**依各 UJ 的 Climax 數值逐條驗收（如 UJ-2「10 秒內回覆」、UJ-3「毛利率 20.0%」、UJ-1「批次 B-20260415-001 數量 120」），全數通過才計為達成；前提是種子資料已就位。Validates FR-9, FR-12, FR-14, FR-17, FR-22, FR-23, FR-27, FR-28。
- **SM-3**：**帳面等式一致率 100%** — 任一時間點滿足 `Σ所有位置餘額（含在途） = Σ入庫 − Σ出庫 + Σ盤盈 − Σ盤虧與報廢`，且 `實體倉合計 = Σ所有位置餘額 − 在途量`。Validates FR-9, FR-10, FR-11, FR-13, FR-24, FR-30。
- **SM-4**：**實盤抽樣準確率 ≥ 95%** — 每倉每月抽樣 20 個位置實盤，實盤數量 = 帳面數量的位置比例；此為帳實相符的外部可觀測指標（SM-3 為帳面等式，無法偵測帳實不符）。Validates FR-13, FR-24。
- **SM-5**：**毛利計算正確率 100%** — 於固定測試案例集（涵蓋多批次 FIFO、整單固定金額折扣與分攤尾差、盤盈成本認列、跨批次出貨）下，毛利額與毛利率與人工重算一致。Validates FR-5, FR-7, FR-16, FR-17, FR-23, FR-25。

**Secondary**
- **SM-6**：查詢回應時間 — 資料量基準為 5,000 筆庫存餘額列，庫存查詢 2 秒內回應。Validates FR-6, FR-12。
- **SM-7**：無阻斷層級的權限漏洞 — 依 §4.1 權限矩陣逐格測試，越權存取全數被拒絕。Validates FR-2, FR-26。
- **SM-8**：端到端任務時間 — 倉管由「輸入品名」到「回覆業務庫存位置與數量」≤ 30 秒；單次 100 筆品項的位置盤點 ≤ 15 分鐘。Validates FR-12, FR-13。
- **SM-9**：**超賣次數 = 0** — 測試期間所有異動路徑（領用、調出、盤點、調整）後可用量皆 ≥ 0。Validates FR-10, FR-15, FR-18, FR-31。
- **SM-10**：**成本可回溯率 100%** — 每筆銷貨單的成本皆可回溯至批次與入庫紀錄。Validates FR-5, FR-17, FR-19。
- **SM-11**：**盤點差異原因填寫率 100%** — 每筆差異與每張調整單皆有原因代碼。Validates FR-13, FR-30。

**Counter-metrics (do not optimize)**
- **SM-C1**：功能數量 — 不以「功能多寡」作為成功依據，寧可少而準確，避免為了攤平而灌入無驗收標準的頁面。
- **SM-C2**：未經驗證的產出不計入完成度 — 任何由 AI 輔助生成的程式碼，未經人為審查與驗證者不得計入功能完成度；**成本、可用量、折扣等領域邏輯必須附對應測試案例** [ASSUMPTION: A10]。

## 9. Assumptions Index

*每條假設都在受影響處以 `[ASSUMPTION: Axx]` 行內標記，可雙向對照。*

- **A1**（§4.9 可用性）產品形態為 Web 桌面瀏覽器，倉管頁面需可於平板操作；v1 不做原生 App 與離線。
- **A2**（§4.9 效能、SM-6）規模假設：1–5 個倉庫、數十名員工、數百至數千個商品／批次。
- **A3**（addendum §1）技術棧定案：**前端 React、後端 Python Flask（以 Flask-Migrate 管理資料庫遷移）、資料庫 PostgreSQL** [NON-GOAL: 技術選型不屬 PRD 範圍]。
- **A4**（§3 成本價、FR-5、FR-17）成本評價採**先進先出（FIFO）**，排序鍵為批次入貨日期、同日以批次編號流水；商品已有庫存後**不可變更評價法**；v1 只做一種評價法並凍結。
- **A5**（FR-1、§4.1 NFR）密碼以 bcrypt/argon2 單向雜湊儲存、至少 8 字元、首次登入須改密、鎖定 15 分鐘；操作紀錄永久保存；外部工具以最小權限帳號存取，v1 不實作權杖。
- **A6**（§4.9 語言、§8）介面與文件僅繁體中文，不做多幣別與多時區。
- **A7**（FR-32、FR-19、FR-28）v1 建立**最小客戶主檔**（客戶名稱、聯絡人、電話），銷貨單與寄貨單引用客戶而非自由文字。（原假設為「不建客戶主檔」，因 FR-19 查詢與寄貨追蹤皆需要客戶識別而修訂。）
- **A8**（FR-2、§5）權限僅以五種固定角色區分，不提供自訂權限組合。
- **A9**（§4.9 備份、可攜性）部署為單一主機的傳統部署，課程階段以匯出 SQL 與種子資料作為備份替代。
- **A10**（SM-C2）成果品質以人工審查與驗證為準，AI 輔助生成的程式碼須經人為驗證後才計入完成度。
- **A11**（FR-4）商品編號採 `IT-` + 6 位數字流水格式。
- **A12**（FR-16、§3 毛利門檻）毛利門檻預設 10%，為全公司單一值，可由管理者設定；與商品級「預估毛利目標」用途不同。
- **A13**（FR-14、§3 商品組合）提供**商品組合**（常用商品組）一鍵套用功能。
- **A14**（FR-13、FR-30）盤點差異與調整單需管理者核准後才調整帳面。
- **A15**（§3 安全庫存水位）v1 水位為**人工設定值**，不依用量自動計算。
- **A16**（FR-4、§5）v1 每個商品僅單一單位，不支援箱／盒換算。
- **A17**（FR-5）批次支援選填有效期限欄位，v1 僅記錄與排序，不做到期主動提醒。
- **A18**（FR-18）調貨單記錄需求來源欄位，供調撥原因分析。
